**Auditor:** Supervisor de Calidad y Seguridad

## Pruebas que sí pasaron (para no perder el crédito donde corresponde)

- **SQLi en login:** parámetros, no concatenación; `' OR 1=1--`, `admin'--`, `' OR '1'='1` → 401 `CREDENCIALES_INVALIDAS`.
- **Token expirado, alterado y `alg:none`:** 401 `TOKEN_INVALIDO`.
- **Reuso de refresh (secuencial):** 401 `SESION_COMPROMETIDA` y revocación de la familia; el token rotado deja de servir.
- **Cierre doble de OP:** OP terminada → 409 `OP_ESTADO_INVALIDO`; VENDEDOR → 403; cantidades negativas/cero/merma > 0,9 → 422.
- **Stock:** constraints `ck_producto_stock_no_negativo` y `ck_insumo_stock_no_negativo` **validadas**; sobreventa no deja stock negativo (rollback); kárdex con saldo corrido.
- **Cobranza:** sobrepago → 422 `MONTO_EXCEDE_SALDO`; monto negativo/cero/texto/medio inválido → 422; CxC inexistente → 404.
- **Autorización de rutas:** VENDEDOR no puede `/kardex` (403) ni cerrar OP (403); GERENTE no puede `/parametros` (403); IGV fuera de rango → 422.
- **Cabeceras:** Helmet activo; body limit 256 KB; `pino` JSON; `SIGINT`/`SIGTERM` con `app.close()` + `pool.end()`.
- **Typecheck:** `tsc` de API y web → exit 0.
- **Compose de producción:** `docker compose --env-file ... config --quiet` → exit 0; servicios `postgres, api, backup, caddy`.

## ¿Listo para producción? **No**

No autorizo el despliegue. Estas son las condiciones mínimas de salida, en orden de riesgo:

1. **Secretos:** eliminar el fallback de `JWT_SECRET` y `PGPASSWORD`; inyectar secretos desde el gestor; fallar el arranque si faltan; rotar y probar que el token por defecto ya no entra (C-01, M-05).
2. **Autorización real:** field-level allowlist y scoping por recurso; CLIENTE/SOPORTE sin datos de negocio; tests de contrato que fallen con `costo`, `margen`, `utilidad`, `cpp` o cartera ajena (C-02, H-03, H-04).
3. **Credenciales y autenticación:** quitar demo del bundle y de la semilla; Argon2id+pepper; mínimo 12; MFA TOTP ADMIN/GERENTE; lockout por cuenta; tiempos constantes; `trustProxy` restringido; rate-limit por IP+cuenta (C-03, C-06, C-09, H-05, H-06).
4. **Dinero e inventario:** secuencia de correlativo; stock/limite de crédito/CxC en la misma transacción; CREDITO sin cliente = 422; 0 ventas con 500 en carga (C-05, C-07, H-02, H-03).
5. **Idempotencia:** obligatoria, atómica, por usuario/ruta/body, 409 en reuso distinto, expiración y purga (H-01).
6. **Auditoría:** rediseñar hash con timestamp/canonicalización, lock de cadena, append-only, endpoint de verificación y anclaje Ed25519/R2; reparar la cadena actual (C-04, H-14).
7. **Sesiones:** ventana de gracia 60 s + mutex de refresh; revocación por dispositivo; tokens en almacenamiento seguro (H-07, H-10, M-08).
8. **CI/CD y artefactos:** pipeline verde (typecheck, tests, E2E, cobertura, build web/móvil, escaneo); web con `/api/v1` same-origin; móvil release con `INTERNET` y HTTPS; imágenes por digest y rollback (C-10, H-09, H-16).
9. **Operación:** `/health/live` y `/health/ready`; timeouts HTTP/DB; backups cifrados WAL-G/R2 con restauración ensayada; monitoreo/alertas; sin deriva entre proceso y artefacto (H-08, H-13, M-01, M-10).
10. **Producto:** implementar cobranza, pedidos, venta y cierre/inicio de OP en web/móvil, o retirar los botones y las promesas de offline; ningún botón primario muerto (C-08, H-11).
11. **Accesibilidad:** contraste >=4,5:1, foco gestionado en diálogos, `aria-expanded`/`aria-live`, tablas navegables por teclado (H-12, M-07).
12. **Legal:** consentimiento, ARCO, incidentes, cifrado de PII y retención antes de tocar datos reales (H-15).

**Criterio de re-auditoría:** repetir esta misma batería (tokens forjados, `/datos` por rol, carga de ventas, auditoría, refresh concurrente, build de producción) y exigir **0 hallazgos críticos/altos abiertos**, suite verde y evidencia de restauración. Hasta entonces, el sistema no es apto para producción.
